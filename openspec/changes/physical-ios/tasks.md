# Tasks

Rules that bind every task below (see design.md, Delivery process): the research note precedes the spikes and the spikes precede construction; implementation tasks add failing tests first and record red-then-green; every install is prefixed with `sfw`; each task lands as atomic commits by its implementer; a validation-and-fix phase (build, clippy on all targets with warnings denied, fmt check, `check-paths`, full tests, `openspec validate`, diff review against the spec) runs before the next task starts; measured numbers come from a quiet host and a charged, unlocked device, with the load recorded; the device identifier and the team id never enter a tracked file. Group 1 first, group 2 before 3 to 7, groups 3 and 4 in parallel once the spikes are in (disjoint trees), 5 after 3, 6 after 3 and 4, 7 after 6, 8 after 7, 9 last.
