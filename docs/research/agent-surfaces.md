# Agent surfaces: state of the art

Research note that opens the change adding agent surfaces beside the `mobile-agent` CLI, ahead of its proposal. The maintainer ranked three surfaces after the CLI: an MCP stdio server with profiles, a CDP-subset endpoint that CDP-native tools could attach to, and a `device` provider contributed to agent-browser. The maintainer has since decided that the tool stays standalone: its own MCP server over the daemon, mirroring agent-browser's tool names where the concepts match so that prompts and skills transfer, with the provider route kept as a documented option. `docs/overview.md`, section 7, already lists what an MCP edge needs from this codebase, and `docs/research/protocol.md` read agent-browser's daemon protocol at `d01253d`; neither is restated here. Every claim was read on 2026-10-16 from the sources at the end, pinned where they are versioned: the specification, Claude Code's documentation, schemars and Playwright through Context7; Cursor's, Codex's and Claude Desktop's documentation on the vendors' sites; the repositories at the commits named; the issues on GitHub. Four things were measured for this note on the project's measurement host (Apple M1 Max) with throwaway probes that were not kept: the size of an rmcp server, the tool lists of agent-browser 0.37.1 and Maestro 2.10.0 (the versions installed there), and the daemon's snapshot replies on a fake target, built from `ea056bb`.

Out of scope: building any surface, authorization and remote deployment over HTTP, the decision-model hook and Android video streaming.

## Findings in brief

- **MCP's current revision is 2026-07-28, and it is stateless.** It removes the `initialize` handshake, protocol-level sessions and `ping`; each request carries its version and the client's capabilities in `_meta`, servers MUST answer `server/discover`, `subscriptions/listen` replaces `resources/subscribe`, server-initiated requests become results the client answers on a retry, tasks move to an extension, and Roots, Sampling and Logging are deprecated. State across calls is "an explicit handle" passed as an ordinary tool argument. A server that speaks only this revision fails every legacy client, and clients are mixed: Claude Code's v2 runtime asks stdio servers for it, agent-browser's server speaks 2025-11-25 and older. rmcp 3.5.1 and agent-device answer both eras.
- **A device server gets tools, inline images and per-request progress; nothing it pushes reaches the model portably.** Tools take JSON Schema 2020-12 inputs and outputs and carry annotations that clients treat as untrusted hints; results hold text, base64 images and structured JSON; resources are for the host to place and prompts for the user to pick. Change notifications go to the client; the one path into the model's context, Claude Code's `claude/channel`, is a research preview on an allowlist that a 2026-07-28 connection cannot carry.
- **The four clients differ where a device server is concerned.** Claude Code defers tool schemas behind tool search, cuts server instructions at 4,096 characters, saves a text result over 50,000 characters or 25,000 tokens to a file, shows images inline, aborts a stdio call silent for 30 minutes and backgrounds one still running after 2. Codex gives a call 60 s by default, wants the first 512 characters of the instructions self-contained, takes `enabled_tools` and `disabled_tools`, and when a result has `structuredContent` shows the model only that JSON and drops its images. Cursor keeps tool names in context and the descriptions in files, and attaches images; Claude Desktop installs binary servers as desktop extensions and lets a conversation switch a connector's tools off.
- **rmcp is mature and costs about 2.9 MB.** The official SDK, Tier 1, at 3.5.1 of 2026-10-05, with 20.2 million downloads in 90 days and three major versions in 2026, has `#[tool]` macros over schemars, a stdio transport, progress through the request's peer and cancellation through its token. A three-tool stdio server built on it measured 3.43 MB against 0.54 MB for a serde_json-only loop, and needs 22 crates this workspace's lockfile lacks; the CLI is 1.64 MB and links clap and serde_json alone. agent-browser (Rust) and agent-device (TypeScript) write their servers by hand.
- **No schema can be derived from the code as it stands.** The daemon's handlers read parameters by name from an untyped map, 42 lookups, and build replies with `json!`; the CLI maps clap's types onto a map, and the harness reads reply fields by name. Typed requests and replies deriving serde and schemars, in one crate, would give the daemon, the CLI, the harness and an MCP server one schema; tool inputs must stay flat objects, since Claude's API refuses `anyOf`, `oneOf` and `allOf` at a schema's root.
- **Mobile MCP servers pay for verification in turns.** mobile-mcp (33 tools), Appium's (31), Maestro's (10) and agent-device's (59 commands and `help`) list the screen with refs or ids, act by ref, coordinates or YAML, and return screenshots inline (mobile-mcp at 1024 px, Maestro at 2000) or as paths (Appium, agent-device); none pushes a change. Their issues put the cost in the agent's loop: a signup through mobile-mcp took 186 turns, 71 screenshots and 16.3 million input tokens, most turns checking whether the last action had done anything; one Appium session about 80 calls and 15 million input tokens; a Maestro `inspect_screen` 4 to 6 thousand tokens for 10 to 20 actionable nodes.
- **agent-browser's MCP server wraps its CLI, and its providers are CDP endpoints.** It runs the binary with `--json` per call, lists 156 tools in nine profiles (the default `core`, 29 tools, came to 62,720 bytes of definitions on 0.37.1), names them `agent_browser_<verb>` with `selector` for a ref, returns a screenshot inline beside its path, always with `structuredContent`, and sends no progress. A provider returns a CDP WebSocket URL; new ones are meant to be plugins whose `browser.provider` capability returns a `cdp_url`, automation staying in agent-browser; its one other backend, WebDriver for Safari, is wired into the daemon's state. A `device` provider needs a CDP endpoint or a backend inside agent-browser's 18,378-line `actions.rs`.
- **A CDP subset would carry none of the tools that speak CDP.** agent-browser's daemon uses 106 CDP method and event names of 13 domains, and its fill and focus run JavaScript on DOM nodes through `Runtime.callFunctionOn`, which a native screen has nowhere to run; Playwright's `connectOverCDP` takes Chromium alone; Metro's inspector proxy registers any device but lists its pages as `type: "node"` for JavaScript debuggers, and React Native's inspector agents handle 24 methods with no DOM, Accessibility or Input domain. The value is low and the cost high.
- **Design inputs, measured here.** On a fake emulator's 500-cell screen `snapshot -i --json` replies 45,164 bytes, 21,482 of them the `refs` map that repeats the listing's roles and names, and an unchanged delta 302 bytes. A default screenshot, 460x1000, costs about 612 of Claude's visual tokens. A target runs its commands in arrival order and the daemon has no cancel, so a wait a client gave up on holds the target until its timeout, up to 600 s; a claim is released only by `close`, which stops the app.

## The Model Context Protocol

The specification's repository, read at `86f6e0c` (2026-10-14), with the revision tagged at `5f5440b`; through Context7 (`/websites/modelcontextprotocol_io_specification_2026-07-28`).

### The 2026-07-28 revision

The changelog lists nine major changes since 2025-11-25. Protocol-level sessions and the `Mcp-Session-Id` header are removed, and list endpoints "no longer vary per-connection" (SEP-2567). The `initialize` handshake is removed: every request carries `io.modelcontextprotocol/protocolVersion` and `io.modelcontextprotocol/clientCapabilities` in `_meta`, and a mismatch returns `UnsupportedProtocolVersionError` (SEP-2575). Servers MUST implement `server/discover`, which returns the supported versions, the capabilities and `instructions`. `subscriptions/listen` is one long-lived stream for the change notifications a client opts in to, while progress and log notifications stay on the stream of their own request. `ping` and `logging/setLevel` are removed. Tasks move to the extension `io.modelcontextprotocol/tasks`, polled with `tasks/get` (SEP-2663). Elicitation, sampling and roots requests come back inside an `InputRequiredResult` that the client answers by retrying the request (SEP-2322), and every result carries `resultType`. Streamable HTTP loses resumability. Roots, Sampling and Logging are deprecated, removable from the first revision released on or after 2027-07-28 (SEP-2577). `inputSchema` and `outputSchema` may use any JSON Schema 2020-12 keyword and `structuredContent` may be any JSON value (SEP-2106), and servers SHOULD list tools in a deterministic order "to enable client-side caching and improve LLM prompt cache hit rates". The versioning page's matrix: a modern client against a legacy server fails, a legacy client against a modern-only server fails, and a dual-era server "selects its behavior from how the client opens", an `initialize` getting legacy semantics scoped to the stdio process. On state the tools page is plain: "MCP has no protocol-level session"; a server that needs state returns "an explicit handle from a creation tool", states its lifetime in that tool's description, and answers an expired handle with a tool execution error.

### What it offers a device server

| Feature | What the revision says | For mobile-agent |
|---|---|---|
| Tools | `name` (1 to 128 of `A-Z a-z 0-9 _ - .`, unique per server), `title`, `description`, `inputSchema` (an object schema, 2020-12 unless `$schema` says otherwise), optional `outputSchema` | one tool per action or verb, a tool list fixed per process |
| Results | `content` of text, image, audio, resource links and embedded resources; `structuredContent`, conforming to `outputSchema`, which "SHOULD also" appear as serialized JSON in a text block; `isError: true` for execution errors, which clients SHOULD show the model, against JSON-RPC errors for requests that cannot run | the envelope's `code` and message as an execution error |
| Annotations | `readOnlyHint` (default false), `destructiveHint` (default true), `idempotentHint` (false), `openWorldHint` (true); clients "MUST consider tool annotations to be untrusted unless they come from trusted servers" | `snapshot`, `get`, `wait`, `screenshot`, `devices`, `status` marked read-only |
| Images | `{"type": "image", "data": <base64>, "mimeType"}` in a result; `blob` in a resource | a screenshot inline instead of a path |
| Resources | "application-driven", the host deciding what enters the context; URI templates (RFC 6570); `audience` and `priority` annotations; updates through `subscriptions/listen` | a target's latest frame or listing as a resource, which reaches the model only when the client includes it |
| Prompts | templates "designed to be user-controlled" | the agent guide, `/server:prompt` in Claude Code |
| Progress | a `progressToken` in the request's `_meta`; `notifications/progress` with increasing `progress`, optional `total` and `message`, rate-limited | a wait's progress, which keeps an idle timer alive |
| Cancellation | on stdio the client MUST send `notifications/cancelled`; over HTTP closing the response stream cancels; senders SHOULD time out, MAY reset the clock on progress and "SHOULD always enforce a maximum timeout" | the daemon has nothing to cancel (below) |
| Elicitation | form or URL requests, in this revision an `input_required` result answered on a retry | asking a person to enter an iPhone's passcode for "Enable UI Automation" at a runner's start, or to confirm a `force` takeover |
| Subscriptions | `toolsListChanged`, `promptsListChanged`, `resourcesListChanged`, `resourceSubscriptions`, each opted in | notifications reach the client, not the model |
| Logging | deprecated: log to stderr on stdio | |
| Tasks | an extension: a durable handle polled with `tasks/get`, given input with `tasks/update` | a long wait as a task; the extension support matrix has no column for it |

**Transports.** On stdio the client launches the server; messages are JSON-RPC, one per line with no embedded newline, the server may log to stderr and "MUST NOT write anything to its stdout that is not a valid MCP message", and in this revision it writes no requests at all. The framing "works unchanged over Unix domain sockets". Streamable HTTP is one POST endpoint answering with a JSON object or a per-request SSE stream; this revision removed its GET stream, sessions and resumability, and it MUST validate `Origin` (403 when invalid) and SHOULD bind to localhost when local.

## Rust SDKs and schemas

### rmcp

`modelcontextprotocol/rust-sdk`, read at `5d9935d` (2026-10-15); 3.5.1 on crates.io (2026-10-05), MSRV 1.88, Tier 1 in the specification's SDK list for 2026-07-28, a tier that requires every conformance test to pass. 68 versions since 2025-03-16, with majors on 2026-03-03 (1.0.0), 2026-06-29 (2.0.0) and 2026-07-28 (3.0.0, the day of the revision); release-plz derives the bumps from conventional commits and runs cargo-semver-checks, and the move to 3.x has a migration guide. 36.5 million downloads, 20.2 million in the last 90 days. It "implements the stable MCP 2026-07-28 specification while remaining fully compatible with the 2025-11-25 release and earlier"; the probe below answered `initialize` at 2025-11-25 and `server/discover` with five versions, 2024-11-05 to 2026-07-28, and listed its tools sorted by name. Default features are `base64`, `macros` and `server`, which brings schemars; `transport-io` is stdio. `#[tool_router]` on an impl and `#[tool(description = …, annotations(read_only_hint = …, destructive_hint, idempotent_hint, open_world_hint))]` on its methods generate the tools: a `Parameters<T>` argument, `T: Deserialize + JsonSchema`, becomes the `inputSchema` with its doc comments as descriptions, a `Json<T>` return the `outputSchema` and `structuredContent`, and `#[tool_handler]` adds `instructions`. A handler that takes the `RequestContext` reads the `progressToken` from its `meta` and calls `ctx.peer.notify_progress(…)`, and its `ct`, a `CancellationToken`, "will be cancelled when the CancelledNotification is received". `CallToolResult::error` is an execution error the client shows; `McpError` a protocol error that clients "render opaquely".

**Alternatives.** rust-mcp-sdk 2.0.0 (314 thousand downloads), pmcp 2.22.7 (131 thousand) and turbomcp 4.0.0-alpha.5 (36 thousand); the specification lists only rmcp for Rust. Two servers of this survey use no SDK: agent-browser's `cli/src/mcp.rs`, 5,375 lines of Rust over serde_json, legacy era only, and agent-device's `src/mcp`, 1,939 lines of TypeScript that serve both eras by hand ("the spec's dual-era server"). Maestro uses the official Kotlin SDK (Tier 3), mobile-mcp the TypeScript SDK 2.0, the version that carries the 2026-07-28 revision, and Appium's server FastMCP over the 1.x SDK.

**What it costs, measured.** The probe: rmcp 3.5.1 with its default features and `transport-io`, tokio's current-thread runtime and three tools (`snapshot` with two optional flags, `click` with a target, `screenshot` returning an image), built by `cargo build --release` (no LTO) with Rust 1.98.1 for aarch64-apple-darwin: 3,429,776 bytes, 32 s from a clean target directory. The same loop over serde_json alone, answering `initialize`, `tools/list` and `tools/call` by hand: 536,944 bytes. The probe's lockfile holds 79 crates, 57 already in this workspace's `Cargo.lock` (tokio, serde and serde_derive among them, through `crates/android`, `crates/ios` and `crates/bench`) and 22 not: rmcp, rmcp-macros, schemars, schemars_derive, darling's three crates, ident_case, pastey, ref-cast's two, dyn-clone, serde_derive_internals, chrono's time-zone crates, and seven that build only for Windows, Android or Haiku. The CLI built from `ea056bb` is 1,641,712 bytes and depends on clap and serde_json alone; the daemon is 15,409,856 bytes without the embedded Android agent and already links tokio.

### Schemas from the daemon's types

`crates/daemon/src/wire.rs` parses a request into `{id, action, session, params: Map<String, Value>}` and gives the handlers accessors by name (`str`, `flag`, `u64`, `f64`, `required_str`, `strings`), 42 lookups in `handlers/`; replies are `Value`s built with `json!` (on 45 lines of `handlers/act.rs`, 10 each of `view.rs` and `mod.rs`) and written by `reply_line` in agent-browser's field order. The CLI's `args.rs` holds clap derive types per command, and `request.rs` turns them into the same untyped map; the harness's adapter, `crates/bench/src/cli/mod.rs`, reads `dispatchMs`, `frameChangeMs` and the rest from a `Value` by name. Nothing types the 18 actions, so a schema has to be written by hand or the types introduced. schemars 1.2.3 derives a 2020-12 schema (draft-07 on request) that follows serde's attributes (`rename_all`, `default`, `deny_unknown_fields`) and turns an untagged enum into `anyOf`; in the probe an `Option<bool>` became `"type": ["boolean", "null"]` and doc comments became descriptions. One crate of request and reply structs per action, deriving `Deserialize`, `Serialize` and `JsonSchema`, would let the daemon parse into them, the CLI build them, the harness read them and an MCP server publish them as `inputSchema` and `outputSchema`, and could write the published output schema the protocol note asked for. Two shapes need care: `click` takes `target` or `x` and `y`, and `data.snapshot` is text or an object depending on `delta`. Claude's API refuses a combinator at a schema's root, which Claude Code flattens and other clients need not, so tool inputs stay flat objects with optional fields checked by the server, as mobile-mcp's click takes `ref` or `x` and `y`.

## agent-browser

`vercel-labs/agent-browser` @ `dac13bb` (2026-10-15), version 0.39.1; Apache-2.0, 44,075 stars, twelve releases between 2026-08-11 and 2026-10-13, all 0.x.

### Its MCP server

`agent-browser mcp [--tools …]` is a hand-written stdio server (`cli/src/mcp.rs`) at protocol 2025-11-25 and three older versions, answering `initialize`, `ping`, `tools/list` (64 tools a page), `tools/call` and `shutdown`: no resources, prompts, progress or cancellation. Each call runs the current binary with `--json` under a timeout of 120 s unless the call's `timeoutMs` says otherwise, so the CLI's output stays the MCP contract (`docs/research/protocol.md`). There are 156 tools in nine profiles, `core` the default with 29, then `network`, `state`, `debug`, `tabs`, `react`, `mobile`, `webmcp` and `all`; on 0.37.1, `core` listed 29 tools in 62,720 bytes of definitions and `all` 156 in 325,590, a median of 14 properties a tool, since every tool repeats the shared arguments (session, namespace, state restore, allowed domains, CA trust, idle timeout, extra CLI arguments, timeout). Tools are `agent_browser_<verb>`: `snapshot` (`interactive`, default true, `compact`, `depth`, `selector`, `delta`, `full`), `click` and `fill` with `selector` for "an element by @ref or CSS selector", `type`, `press` (`key`), `scroll` (`direction`, `amount`, `selector`), `wait_ms`, `wait_for_selector`, `wait_for_text`, `screenshot` (`path`, `format`, `quality`, `annotate`, and `ifChanged`, "return image content only when pixels changed"), `get_text`, `get_box`, `diff_snapshot`, `batch`, and in `mobile` `tap`, `swipe` and `device` ("List available iOS simulators"). Annotations are `readOnlyHint` and `openWorldHint`; the instructions ran to 264 characters on 0.37.1. A result is the rendered text, the image when the reply names a PNG or JPEG path under 10 MiB, and always `structuredContent` with the exit code, stdout, stderr and the parsed reply, the code noting that "Most hosts put text content in the model context". Under Codex's conversion that `structuredContent` would replace both the text and the image (an inference from the two codes, not run).

### Providers, plugins and the daemon

`cli/src/native/providers.rs` connects to AgentCore, Browserbase, Browserless, Browser Use and Kernel by a `match` on the name, and "each provider returns a CDP WebSocket URL", with `direct_page` when "the WebSocket IS the page session (no Target.* commands)"; any other name goes to a plugin. Plugins (`cli/src/plugins.rs`, `docs/content/docs/plugins.mdx`) are local executables speaking `agent-browser.plugin.v1`, one JSON request on stdin and one reply on stdout, with the capabilities `credential.read`, `browser.provider` (a reply of `cdp_url`, `direct_page`, `cleanup`), `launch.mutate` and `command.run`. The documentation says new cloud providers "should usually start as plugins" and "Keep browser automation itself in agent-browser. A plugin should provide data or launch configuration, then let agent-browser continue driving the browser." The one backend besides CDP is WebDriver: Appium for Safari on an iOS Simulator or device, and safaridriver for Safari on the Mac, held in the daemon's `DaemonState` beside the CDP browser, behind a `BrowserBackend` trait of `navigate`, `get_url`, `get_title`, `get_content`, `evaluate`, `screenshot`, `click`, `fill` and navigation, written "so actions.rs can remain backend-agnostic in the future", with a list of actions WebDriver cannot do (accessibility audits, screencasts, tracing, routing, HAR). There is no CONTRIBUTING file or template, and releases are "manual, single-PR affairs" whose changelog lists contributors (`AGENTS.md`); 92 of the last 100 merged pull requests, 2026-07-13 to 2026-10-15, came from three accounts.

### The `device` provider, a documented option

Not pursued now. What it would take: agent-browser's provider and plugin interfaces end in a CDP URL, so a provider that wrapped `daemon.sock` would either serve CDP to agent-browser's daemon (next section: not feasible beyond screenshots and input) or need a third backend inside agent-browser, a native-screen sibling of the WebDriver one: its snapshot from the daemon's listing and refs, its actions as daemon requests, its commands without a page (no URL, title, evaluation or network). On this side nothing changes, since the socket is the integration point (`docs/overview.md`, section 7); the published schema above would be agent-browser's contract. On agent-browser's side it is a change to `DaemonState` and to the dispatch in an 18,378-line `actions.rs`, in a project that released twelve times in two months, against a plugin policy that keeps new providers out of core. It would pay off if agent-browser's maintainers asked for non-browser targets or opened a backend interface: one MCP configuration and one skill for web and devices, and agent-browser's reach.

### A standalone server under agent-browser's names

Mirroring means the tool stems and argument names, not agent-browser's code. The daemon's actions map onto `snapshot`, `diff_snapshot`, `click` (and `tap`), `fill`, `type`, `press`, `swipe`, `scroll`, `screenshot`, `get_text`, `get_value`, `get_box`, `wait_ms`, `wait_for_selector`, `wait_for_text`, `open`, `close`, `batch` and `doctor`; `devices` meets agent-browser's `device` (`action: "list"`, iOS Simulators); `wait --settle` has no counterpart (agent-browser's `wait_for_load` waits for page states), nor have `status` and claims. Arguments differ where the daemon took its own names: `target` against `selector`, `maxDepth` against `depth`, the screenshot's `maxDimension` against agent-browser's `format`, `fullPage` and `annotate`, and agent-browser's `snapshot` defaults to interactive. The prefix matters less than the stem: Claude Code names every tool `mcp__<server>__<verb>`, and the specification asks clients to disambiguate. What the standalone server costs: the tool table and its schemas kept in step with agent-browser's names by hand, and none of agent-browser's distribution, its users adding a second server.

## A CDP subset

### What agent-browser's `--cdp` needs

Discovery reads `/json/version`, then `/json/list`, then tries `ws://host:port/devtools/browser` (`cli/src/native/cdp/discovery.rs`). 106 distinct CDP method and event names of 13 domains appear in the daemon's sources (`cli/src/native`, tests included), `Runtime.evaluate` and `Runtime.callFunctionOn` the most often, then names of `Page`, `Target`, `Network`, `DOM`, `Input`, `Fetch`, `Browser`, `Emulation` and `Accessibility`. A snapshot reads `Accessibility.getFullAXTree` with `DOM.describeNode`, `DOM.resolveNode`, `DOM.querySelectorAll` and `Page.getFrameTree`; a click resolves its ref to a backend node, runs `DOM.scrollIntoViewIfNeeded` and `DOM.getBoxModel` and sends `Input.dispatchMouseEvent` at the centre; fill, focus and visibility run JavaScript functions on DOM objects through `Runtime.callFunctionOn`, named 13 times in `interaction.rs` and 14 in `element.rs` (`function() { this.focus(); }`). A device could synthesize an accessibility tree, boxes, input and `Page.captureScreenshot` from its replica; it has no JavaScript realm for those functions, and matching their source text would bind the endpoint to agent-browser's internals.

### React Native's inspector proxy

`facebook/react-native` @ `e04aaf6`, `packages/dev-middleware` (0.87.0-main). Metro serves `/json`, `/json/list` and `/json/version`; a device registers over a WebSocket at `/inspector/device?device=…&name=…&app=…` and answers `getPages` with pages `{id, title, app, capabilities}`, and debuggers connect at `/inspector/debug?device=…&page=…`, their CDP messages forwarded as `wrappedEvent`s. The proxy lists each page with `type: "node"` and a `reactNative` block, checks a debugger's origin and does not authenticate a device, so the daemon could register a page while Metro runs. Behind it, React Native's inspector agents (`ReactCommon/jsinspector-modern`) handle 24 methods themselves (`Page.reload`, `Page.captureScreenshot` behind a flag, `Overlay.setPausedInDebuggerMessage`, `ReactNativeApplication.enable`, `Network.*`, `Tracing.*`, `Runtime.enable` and bindings) and pass the rest to the JavaScript runtime's agent: the debuggers there are JavaScript debuggers and profilers, as agent-device's `cdp` command samples the JavaScript heap "through Metro CDP". None of them drives a UI through DOM, Accessibility or Input domains.

### Other CDP clients

Playwright's `connectOverCDP` "is only supported for Chromium-based browsers" and "is significantly lower fidelity" than its own protocol; Appium speaks W3C WebDriver (`docs/research/protocol.md`).

### Value against cost

No CDP-native tool would drive a native app through a subset: agent-browser needs JavaScript on DOM nodes, Playwright a Chromium browser, Metro's debuggers a JavaScript runtime. The one use the domains do fit is watching and poking a screen, `Page.captureScreenshot`, `Page.startScreencast` and `Input.dispatchTouchEvent`, which a viewer needs and an agent does not. Against that stands a CDP server: a WebSocket endpoint, target discovery, sessions, and methods kept in step with clients that release every week or two.

## Design inputs for the MCP server

- **Sessions.** The revision has no protocol session and recommends handles as arguments; a stdio server is one process per client, so a session name minted per process gives the isolation `--session` gives the CLI (claims, refs, diff baselines, timeouts; `crates/daemon/README.md`, Sessions and claims). agent-browser takes `session` as an optional argument on every tool, mobile-mcp `device` and Maestro `device_id` on every call, Appium an optional `sessionId`; Maestro #3611 shows what a shared port costs. A claim lasts until `close`, which stops the app the session's `open` launched, or until the daemon exits: a server that exits leaves its claim, the next session meets `target_claimed`, and no action releases a claim and leaves the app running.
- **Refs.** Valid only in the session whose snapshots listed them, never reused, and stale once the element goes (README, Refs); a reconnected client that gets a new session meets `unknown_ref` on the refs in its transcript, which the session argument avoids.
- **Listings and deltas.** On the fake emulator's 500-cell screen (`snapshot -i --json` from `ea056bb`): 505 lines, the listing 21,889 bytes, the `refs` map 21,482 more, the reply 45,164; the full listing 22,962 bytes; a first `--delta` 45,183 and an unchanged one 302. At Claude's 3.5 characters a token on models before 4.7 the reply is about 13 thousand tokens, the listing alone about 6 thousand. The text content needs the listing, not the map that repeats it; deltas are relative to the session's last delta snapshot and fall back to the whole listing at 70% of its size (README, Delta snapshots).
- **Long waits.** Waits run to their timeout, at most 600 s, and a target runs its commands in arrival order (`crates/daemon/src/worker.rs`); the protocol has no cancel action, so an MCP cancellation has nothing to stop and the target stays held. Codex gives a call 60 s, Claude Code aborts a stdio call silent for 30 minutes unless progress arrives and backgrounds one past 2 minutes, agent-browser bounds a call at 120 s. Progress notifications keep Claude Code's idle timer alive and show in its task entry; Codex documents no such reset, so a server-side bound under 60 s, or a cancel in the daemon, covers the rest.
- **Screenshots.** The daemon writes a JPEG to a path, quality 80, longest edge 1000 px by default, and replies with its metadata (README, Acting and reading). Claude counts `⌈w/28⌉ × ⌈h/28⌉` visual tokens, about 612 for 460x1000, and refuses images over 2000 px a side in a request holding more than 20 images, earlier turns included. Inline images reach Claude Code and Cursor, and Codex only without `structuredContent`; agent-browser sends both and the path; its `ifChanged` sends an image only when pixels changed, which the mirror's frame hashes already tell on targets with frames.
- **Warnings and failures.** A failure's code and message become an execution error (`isError`), which clients show the model; a `warning` marks a success not to take at face value, so it belongs in the text content, which every client shows unless `structuredContent` replaces it in Codex.
- **Waiting for a change.** The daemon answers one reply per request and pushes nothing (`docs/overview.md`, section 7); MCP's notifications reach the client, not the model, so the portable form is a blocking tool that returns when the replica's revision or the frames move, with a delta, built on what the mirror exposes (`run_until`, `next_wakeup`, `timestamps()`, the revision; `crates/mirror/README.md`).
- **Tool names.** agent-browser's stems with its `selector`, `depth` and `interactive` default, or the daemon's names; the specification allows either, and Claude Code prefixes the server's name.
- **Profiles.** The daemon's 18 actions make about as many tools as agent-browser's `core` profile, whose 29 definitions were 62.7 KB; Claude Code defers schemas, Cursor keeps names, and Codex's `enabled_tools` and `disabled_tools` already subset a server, so a `--tools` flag pays only for a read-only set (snapshot, get, wait, screenshot), which also passes Codex's `writes` approvals without prompts. Playwright MCP opts groups in the same way (`--caps` for vision, PDF, devtools and others) and takes a snapshot for each response unless `--snapshot-mode none`.
- **Instructions.** A card whose first 512 characters stand alone and whose whole stays under 4,096, and the agent guide behind a `help` tool or a prompt (agent-device's split).
- **An unverified mode.** `click` replies once the tap's first frame change and tree delta have come, after about 200 ms when nothing changes, at most 1 s (README, Clicks and their timing). The production-app runs of `openspec/changes/archive/2026-10-15-rn-app-fixes/` measured the steps an agent pays to verify (task 7.5, medians in its two keyboard states): a click by ref 343 and 390 ms, `snapshot -i` 49 and 54 ms, `wait --settle` 111 and 258 ms, a typed `fill` with its read-back 1.42 to 2.43 s and a pasted one 0.61 to 1.05 s. An unverified tap saves at most the watch; checking it costs at least one more model turn, which #450 found to be most of a run. agent-device ships both, its default click "does not confirm that the element received it", with `verify` and `settle` to opt in, and its own instructions tell agents to act with `settle: true`. An unverified mode fits a `batch` of known steps better than an agent's single taps.

## What this project reuses and where it differs

- **Reused.** The daemon's socket and envelope unchanged, its sessions (one per MCP process), the CLI's `client.rs` for discovery, start, version check, retries and the reply wait, the codes and messages as execution errors, delta snapshots, `diff snapshot` and the verified replies as the feedback mobile-mcp's users ask for; from MCP, tools, inline images, annotations, progress and both eras; from agent-browser, the tool stems, the profiles flag and the `ifChanged` screenshot; from agent-device, a short instructions card with the guide behind `help`.
- **Where it would differ.** From agent-browser's server: a request on the daemon's socket per call rather than a process per call, schemas from shared types rather than written beside each tool, progress during waits, and no `structuredContent` beside an image. From the mobile servers: refs a session owns and a stale ref with its own code, actions that report their effect, and a screenshot from the mirror's latest frame. From the ranking: no CDP endpoint and no provider inside agent-browser, both kept as documented options.

## Decisions for the proposal

1. **SDK.** rmcp, dual-era, Tier 1, about 2.9 MB and 22 new crates, three breaking majors this year; or a hand-written loop over serde_json, as agent-browser and agent-device keep, 0.54 MB, with both eras, `server/discover`, progress and cancellation to write and follow.
2. **Where it runs.** `mobile-agent mcp`, adding tokio and the SDK to a 1.64 MB CLI that links clap and serde_json alone, or a binary of its own beside it.
3. **Types and schemas.** A shared crate of request and reply types with serde and schemars, which also changes how the handlers read their 42 parameters; or schemas written by hand for 18 actions.
4. **Names.** agent-browser's stems and argument names (`selector`, `depth`, interactive by default) or the daemon's (`target`, `maxDepth`), and the prefix.
5. **Results.** The listing as text without the refs map; `structuredContent` with an `outputSchema` or not, given that Codex then shows only that JSON and drops images.
6. **Screenshots.** Inline by default with `ifChanged`, or a path, or both; the size bound against 2000 px for many-image requests.
7. **Long waits.** Progress notifications, a server-side bound under Codex's 60 s, and a cancel action in the daemon, given that a target runs its commands in order.
8. **Waiting for a change.** A new daemon action that blocks until the replica or the frames move, and what it returns.
9. **Sessions and claims.** A session per process with an optional `session` argument, and a daemon action that releases a claim without stopping the app, for a server that exits.
10. **Profiles and instructions.** A `--tools` set, read-only at least, or none; the card and where the guide lives.
11. **The unverified mode.** A flag on actions, defaults unchanged, given that verification lives in the reply and an extra turn costs more than the watch.
12. **The provider and the CDP subset.** Recorded, not built: the provider by the maintainer's decision, until agent-browser opens a non-CDP backend; the subset for a viewer at most.

## Risks

- **The revision is three months old.** Clients negotiate it unevenly, and Claude Code's channels do not run on it; a dual-era server carries both behaviours until the legacy era goes.
- **rmcp's cadence.** Three majors in 2026 and releases about weekly; each major is a migration.
- **Client behaviour moves.** Claude Code's description limits changed at v2.1.296, Cursor changed what enters the context in January, Codex's handling of `structuredContent` is an open issue; the limits recorded here are of 2026-10-16.
- **Name drift.** agent-browser is pre-1.0 and released twelve times in two months; mirrored names need a check per release.
- **Token figures.** The listing sizes come from a fake target, and the token conversions use Claude's documented ratio for earlier models; Claude 4.7 and later produce about 30% more tokens for the same text.
