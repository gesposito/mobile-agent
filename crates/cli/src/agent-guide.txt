mobile-agent: a guide for agents

mobile-agent drives Android devices and emulators, iOS Simulators and iPhones.
A daemon keeps a live mirror of each screen, so snapshots answer from memory.
The grammar, refs and JSON output follow agent-browser.

The loop
  1. mobile-agent snapshot -i       list actionable elements with their refs
  2. mobile-agent click @e3         act on a ref from that snapshot
  3. mobile-agent wait --settle     let the screen settle after the action
  4. mobile-agent snapshot -i       snapshot again before the next action
  Act only on refs from your latest snapshot.

Snapshots
  - button "Sign in" [id=login-submit, ref=e4]
  One element per line: role, name in quotes, attributes, the ref last.
  A field's value follows ": ". A line in parentheses, as "(8 more actionable
  items above, 2 of them behind the header, scroll up to reveal)", counts what
  is scrolled away, covered or under the keyboard; a keyboard covers nothing
  when a hardware keyboard shows no keys, iOS's edit menu only its strip. -i
  leaves out what a tap reaches none of, as under a header or a footer;
  snapshot lists it at visible=0% unless a dialog covers it. Both say
  visible=35% of what a tap reaches part of. Every tab has a ref.
  snapshot -i        only elements with refs; start here
  snapshot           every element, texts and system bars too
  snapshot -d 2      at most two levels deep
  snapshot --delta   only what changed since your last delta snapshot

Refs
  Write a ref as @e4; ref=e4 and e4 work too. A ref names one element while
  it stays on screen, and a number is never reused. When the element is gone
  the command fails with code stale_ref: snapshot again and use the new refs.

Selectors
  Where a ref goes, a selector works too: #login-submit (test id),
  text=Sign in (name or value contains it), text==Row 1 (the whole name
  or value), role=switch, or bare text. A selector waits up to the timeout
  for a match, in view or not; a match that is covered or out of view is
  refused at once, as its ref would be. Refs never wait.

Acting
  click @e4 | tap 200 480     tap a ref, a selector, or a point in points
  click @e4 --hold 800        long press
  fill @e2 agent              replace a field's text, then read it back; keys
                              the field took wrong are pasted over (set
                              directly on Android), a warning names them
  type @e2 ' smith'           add key events; without a ref, the focused field
  press Enter | Back | Home   keys; join modifiers with +, as Control+a
  scroll down 600             move the content; -s @e7 scrolls inside @e7;
                              strokes keep off the keyboard and system bars
  scroll down --until '#row-150'   scroll until the element is mostly in view;
                              no stroke carries it past unseen
  swipe up | swipe X1 Y1 X2 Y2   move the finger
  open com.example.app        launch an app; close stops it and frees the target
  A tap goes to the part of an element you can see, and warns when that is
  not most of it. element_covered: less than 8 points of it show from under
  its cover, named as hints name it, a dialog, a button, disabled or not, a
  bar or the keyboard; act on a dialog first, else scroll it out from under
  the view. element_offscreen: none of it in view; close the keyboard or scroll.
  fill's reply says what it read back: verified: text, or length for a
  masked field, from the field's value, a code field's value counting
  only when the text changed it; readFrom: descendants from its boxes,
  readFrom: name from the part of its name the text changed;
  verified: false and reason: no_value_to_read when the field shows
  nothing to read: look at a screenshot. An id on a field's wrapper fills
  the field inside it; on a view holding none, fill and type tap it and
  the keyboard it brings up takes the text. method: keys means typed, direct
  entered in one piece: set on Android and iPhones, pasted on a Simulator,
  which replaces the pasteboard and can show iOS's paste banner; fill
  closes the edit menu a lost paste leaves up.

Waiting
  wait --settle               no tree or frame change for 200 ms, at most
                              3000 ms; settled: false names what kept changing
  wait --text Welcome         until an element shows the text
  wait '#spinner' --state hidden   until it is off screen; also visible,
                              enabled, and attached or detached in the tree
  wait 500                    fixed milliseconds, a last resort
  click waits for the tap's first effect, at most 1 s, so a snapshot right
  after it already sees the change; wait --settle waits out the rest.
  Waits take --timeout MS. The default is the session's (set timeout 5000),
  else MOBILE_AGENT_DEFAULT_TIMEOUT, else 10000.

Reading
  get text @e5 | get value @e2 | get box @e4   in view or not, as inView says
  diff snapshot               what changed since your last snapshot
  screenshot shot.jpg         the latest frame as a JPEG

Output and errors
  --json prints one object: {"success", "data", "error"}, plus "code" and
  "warning" when set. A failure exits with status 1 and always has a
  snake_case code, such as stale_ref, unknown_ref, element_not_found,
  wait_timeout, target_claimed or ambiguous_target; text_mismatch means
  fill left other text in the field, which its message names, and
  covered_by_keyboard that the keyboard covers what you scroll: close it
  (press Back on Android), then scroll again. Without --json, errors go to
  stderr. A warning, such as a degraded snapshot, says to check the screen
  before you trust what is missing from it.

Targets and sessions
  devices lists the targets. With several, pass --device ID or --platform.
  --session NAME keeps target claims and refs apart. A target that another
  session holds is refused with target_claimed, unless you pass --force.

iPhones
  A phone on USB is a target when MOBILE_AGENT_DRIVERS names ios. A command
  on one that is not ready fails with its state as the code: device_locked
  (unlock it), developer_mode_off, not_trusted, disk_image_unmounted,
  no_signing_identity, or automation_not_enabled (approve Enable UI
  Automation on the phone); devices and doctor name the step. It is slower:
  a tree read of a 500-cell screen takes about 0.5 s, and frames come
  19 a second, so settle and waits take longer. Text goes in
  through the runner: method: keys means typed, direct the field's value
  set, not a paste, so the pasteboard is left alone.

Batch
  mobile-agent batch --bail 'open com.example.app' 'snapshot -i' 'click @e3'
  runs commands in order and stops at the first failure. With --json it
  prints one array of {command, success, result, error}.
